# 字体规格

本文档说明 Sarasa Ui PropDigits 的地区矩阵、字重轴映射、数字与标点规则、语言系统路由、竖排与度量规格。全部结构化参数以 [sarasa_pd/spec.toml](../sarasa_pd/spec.toml) 为单一事实来源，下方规格表由脚本自动同步并在单元测试中校验一致。

## 1. 地区与字形来源

全系列共 6 个地区，均以 Source Han Sans VF 2.005R 为 CJK 基底、Inter VF 4.1 为西文/数字来源；CL 在 `SourceHanSansK-VF` 基底上叠加完整 `ShangguSansTC-VF` 1.028 的传统旧字形及 CJK 全宽破折号。全部地区的公开 `cmap` 覆盖范围与 `cmap` format 14（UVS/IVS）均按上游 Sarasa Ui 同地区成品边界对齐，保留完整变体序列（其中 `J` 含 14,795 条，`CL`/`K` 含 330 条，`HC` 含 38 条，`SC` 含 33 条，`TC` 含 26 条）。

- 家族名在菜单中缩写为 `Sarasa Ui PD <地区>`（静态）与 `Sarasa Ui VF PD <地区>`（可变），满足 Windows 31 字符限制；文件名与 ZIP 包名保持 `PropDigits`。
- 静态字体的 `post` 表使用 format 3（不写入持久化字形名）；不保留 Mac（`platformID=1`）`name` 记录。
- 缺字框 `.notdef` 统一采用 Inter 的 656 unit 方框（正斜体分别取自对应 Inter VF）。

## 2. 字重与轴映射

可变字体公开单一 `wght` 轴（范围 `200..900`，默认 `400`），提供 6 个命名实例，并以 `350` 作为隐藏 `avar` 锚点（Source Han 与 Inter 均映射到 350，无命名实例）。静态字体直接由同地区同风格的 VF 在以下 6 个公开坐标实例化得到。

- 构建顺序固定为：先对 Source Han 基底建立公开 `wght` 轴与 `avar` 映射，再把 Inter 轮廓 `gvar` 与 GPOS 变化重映射到同一公开轴空间；顺序不可反转。
- 公开 `600`（SemiBold）对应 Source Han 内部 `500`（Medium）与 Inter `600`（SemiBold）的组合，与上游 Sarasa Ui 一致。
- 斜体由对应风格 `InterVariable-Italic.ttf` 与倾斜 `9.4°`（以 `em/3` 为剪切中心，不剪切最后 4 个 metric phantom points）的 Source Han VF 合成。

## 3. 比例数字与 `tnum`

以下 **37 个码位**默认采用 Inter 比例形态，开启 `pnum` 不改变默认宽度：

| 类别 | 码位或字符 |
| --- | --- |
| 数字 | `0–9`（U+0030–U+0039） |
| 空格 | U+0020、U+00A0、U+2008 |
| 标点与括号 | `, . : ; ( ) [ ] { }` |
| 运算符 | `* + < = > ~ ± × ÷ − ≈ ≠ ≤ ≥` |

- `tnum` 恢复上述字符及第 38 个码位 `U+002D`（连字符）的 Inter 等宽形态；0–9 数字在每个命名字重及 VF 任意 `wght` 采样点严格等宽。
- `tnum + zero` 切换至等宽斜线零，与其余等宽数字保持完全相同的步进变化曲线。
- Inter 烘焙顺序固定为 `tnum` → `ss03` → `cv10` → 37 码位恢复 `pnum`，并原地扩充 Inter `calt` 覆盖表，使烘焙后的数字与符号继续参与上下文规则。
- 保留 Inter 原生 GSUB lookup 顺序及全部无动作保护规则（`calt` 箭头保护如 `x<-1`、`frac` 日期保护如 `2026/11/19`、`dlig` 下 `Left:1` 不误上浮、`H(H)` 开 `sups`/`subs` 给 `.case` 括号）。

## 4. 标点、语言系统与排版规则

### 4.1 标点规整与默认区域规则

- 沿用 Sarasa Ui/pwid 规则烘焙比例引号与省略号，并规整半宽符号与韩文字形宽度（韩文含 GSUB 闭包向上取整至整 em 并居中，零步进组合字母左移 `0.04 em`，共享字形的 `U+FFA0` 与片假名中点 `U+30FB` 保持各自原生语义；烘焙 `pwid` 前先固化 `cmap` format 14 默认变体，保证 `‘︁`、`’︁` 全宽变体不被缩小）。
- 横排西文标点按文字系统与语言切换，六地区一致：

| 文字系统 / 语言 | 省略号 `…` | 单破折号 `—` | `——` / `⸺` | `———` / `⸻` |
| --- | --- | --- | --- | --- |
| `latn`/`cyrl`/`grek`/`DFLT` 未标语言或西文语言 | 下沉、比例宽 | 西文比例形态 | 西文比例形态 | 西文比例形态 |
| 显式 `zh-Hans` / `zh-Hant` / `zh-HK` / `ja` | 居中、全宽 | 全宽 | 2em | 3em |
| 显式 `ko` | 居中、全宽 | 韩文比例形态 | 2em | 3em |
| `hani`/`kana`/`hang`/`bopo` 未标语言 | 居中、全宽 | 随地区（`K` 用韩文比例形，其余全宽） | 2em | 3em |

- `bopo` 脚本默认接入本地区 CJK 标点路由，避免注音串中的省略号与破折号退回西文形。

### 4.2 语言系统合并与特有规则

- 精确按 `(ScriptTag, LangSysTag)` 合并 Source Han 与 Inter 的 GSUB/GPOS，不跨语言静默回退；再将 `DFLT/dflt` 特性共享给远东文字（`hani`/`kana`/`bopo`/`hang`）默认语言、所有文字下的远东语言（`JAN`/`KOR`/`ZHS`/`ZHT`/`ZHH`），以及西里尔/希腊默认语言（`cyrl/dflt`、`grek/dflt`），竖排特性 `vert`/`vrt2` 保留各自路由。
- 古韩文 L+V+T 直接继承 Source Han VF 完整的 `ccmp` 链式上下文忽略规则，在韩文、未标语言与西文语言下合为单音节，在中文/日文语言下按 Source Han 原生规则各占一格。
- GPOS `PairSet` 统一按第二字形编号升序排列，避免 HarfBuzz 二分查找漏读字偶距。
- CL 中由尚古 1.028 覆盖的汉字强制检查全宽 `1000` 并冻结水平步进变化（修正 `巅`、`拼`、`绿` 等），同时修正 `㪉㪘㪣㪰` 的 GDEF 类别为间距基字（Base，而非 Mark）。

## 5. 竖排与 `chws`/`vchw`

- 竖排破折号与省略号完全采用 Source Han 原生 `ccmp`/`locl`/`vert`/`vrt2`（含 2em/3em 竖排连字），不再合成 1em 竖排片段，也不注入 GPOS `curs`；横排连续 `U+FE31` 与关闭 `vert`/`vrt2` 时的破折号均各自独立成形。
- 通过固定 `chws_tool`（`east-asian-spacing`）注入 `chws` 与 `vchw` 标点挤压特性；斜体按剪切前的正体轮廓墨迹判定标点左右空白，防止粗体斜切标点越过中线失去挤压效果。

## 6. 度量、变化表与光栅设置

- 水平度量沿用上游 Sarasa 垂直度量基准：`unitsPerEm = 1000`、`hhea.ascent = 969`、`hhea.descent = -241`、`hhea.lineGap = 0`、`OS/2.sTypoAscender = 968`、`sTypoDescender = -241`、`usWinAscent = 968`、`usWinDescent = 241`。
- VF 移除 `VORG`/`VVAR`，竖排度量统一用 TrueType `vmtx` 与 `gvar` 垂直幽灵点表达；`HVAR` 直接由最终 `gvar` 构建，保证 VF 运行时步进与静态实例化结果逐字形一致；`MVAR` 覆盖下划线与删除线随字重的变化。
- VF 在最终化时合并同支撑 `gvar` 元组，并对斜体 `gvar` 执行容差 0 的无损 IUP 重优化以压缩体积；所有有轮廓字形强制 `hmtx.lsb == xMin` 且置位 `head.flags` bit 1。
- 置位 `OS/2.ulUnicodeRange2` bit 57（辅助平面汉字），按最终布局重算 `OS/2.usMaxContext`，`head.modified` 由环境变量 `SOURCE_DATE_EPOCH` 或 `spec.toml` 固定时间戳决定以实现确定性输出。
- VF 与 unhinted 静态使用 `gasp {0xFFFF: 0x000F}` 与仅开启 smart dropout 的最小 `prep`，不含逐字形指令、`fpgm` 或 `cvt`。该 `prep` 仅开启抗断笔补点（`SCANCTRL`/`SCANTYPE`），不做网格拟合，也不会改变轮廓坐标；对依赖“完全无 `prep` 表”来判断字体为纯无指令的少数旧检测工具而言，会将其识别为带基础光栅设置（属有意保留，与上游及主流无 hint TrueType 字体一致）。
