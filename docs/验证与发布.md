# 验证与发布

本项目将“必须满足的硬性检查”（`sarasa_pd check` 与单元测试）与“人工审阅的对照与样张”（`sarasa_pd compare`、`sarasa_pd samples`）清晰分离：前者作为打包与发布门禁，后者用来快速发现与上游或前版的任何意外漂移。

## 1. 自动化验证（硬门禁）

### 单元测试（本地与 GitHub Actions CI）

```powershell
python -E -s -X utf8 -m unittest discover -s tests
```

CI 工作流 [.github/workflows/check.yml](../.github/workflows/check.yml) 在全新 Ubuntu 环境中按 [requirements.lock](../requirements.lock) 哈希锁定安装依赖，核验 `sarasa_pd env` 并运行全部单元测试（不允许跳过任何用例），包含：

- 规格文件、命名/文件名规则、环境隔离与锁文件校验；
- 归档 SHA-256 与路径穿越/符号链接拦截（含 `tar.xz` 包内相对软链接与越界链接拦截）；
- 子集化保留 `cmap` format 14（UVS/IVS）且不泄漏未请求码位；
- VF 轴映射、`pwid` 烘焙与 UVS 保护、韩文宽度归一与 `U+FFA0` 隔离、Inter `calt` 扩充、语言系统精确合并、标点路由幂等与竖排 3em 三段切分（含斜体 `gvar` 切点增量）、CL 汉字全宽/GDEF/OS/2 修复、`gvar` 合并与 IUP 压缩、`MVAR`/`HVAR`；
- 静态实例化去重叠与正体去重叠后斜切联动、元数据、斜体 hint 零容差精确重映射（含 `post` format 3 位移未编码字形、禁止静默跳过与 `.hint.gz` 键序规范化）与 `cvt` 补零；
- 规则与二进制检查的反例测试（故意破坏 UVS、缺参照、bit 57、表级框架任一字段、无 hint 光栅外观、CJK hint 竖向位移异常、去指令轮廓等必须被拦下）；
- 确定性 21 ZIP 打包（含打包前门禁核对与包内 README 链接改写）与篡改检测；
- 文档规格表格同步与全部源码/文档 UTF-8 无 BOM、LF 换行校验。

README 与 `docs/` 中的规格表格由 `sarasa_pd docs` 按 [sarasa_pd/spec.toml](../sarasa_pd/spec.toml) 生成：改了规格后运行下面的命令同步，加 `--check` 只核对、不写入。单元测试也会核对，表格过期或标记写错都会失败。

```powershell
python -E -s -X utf8 -m sarasa_pd docs
```

### 全量成品检查（`sarasa_pd check`）

`sarasa_pd check` 将 hinted 静态的 FreeType 严格光栅扫描分为两档：

- **日常开发快检（`--ft-mode fast`，默认）**：扫描 **9–20 px 逐字号 + 24–128 px 每 4 px**（共 39 个字号，全字形），耗时约全量的 1/3；配合 `--regions SC --weights Regular,Heavy` 可在几分钟内跑完日常改动核验。
- **发版前全量硬门禁（`--ft-mode full`）**：扫描 **9–128 px 全 120 个字号 × 全字形**，72 个 hinted 静态独享约 4.5–5 小时（每字体约 580 万次严格光栅化），发版前必须全量通过。

```powershell
# 日常开发快检（默认 --ft-mode fast）
python -E -s -X utf8 -m sarasa_pd check --stage all --root fonts --jobs 4 --ft-mode fast

# 局部快速核验（例如只查 SC 的 Regular 与 Heavy）
python -E -s -X utf8 -m sarasa_pd check --stage all --regions SC --weights Regular,Heavy --root fonts --jobs 4 --ft-mode fast

# 发版前全量硬门禁（9–128 px 逐字号全字形扫描）
python -E -s -X utf8 -m sarasa_pd check --stage all --root fonts --jobs 4 --ft-mode full
```

逐字体执行以下检查（`check` 会自动准备并校验固定上游参照与 `ots-sanitize 9.3.0`，缺少参照直接失败不静默跳过；全部 156 字体在 `--ft-mode full` 且启用 OTS 通过后写入 `.check-passed.json`，`package` 打包前默认强制核对）：

1. **产品规则检查**（`sarasa_pd/checks/rules.py`，纯基于 GID 与几何度量，不依赖 `post` 字形名）：
   - `cmap` 覆盖与 `cmap` format 14（UVS/IVS，含默认/非默认映射状态）与同地区上游成品双向严格一致，无悬空变体目标；
   - 37 个码位默认比例宽、`pnum` 不改变默认宽度；`tnum`（含 `U+002D`）与 `tnum + zero` 严格等宽（VF 每 25 轴单位全采样）；
   - 上下文与保护回归：`1:2`/`1:`/`:2` 上浮，`1:a`/`a:2`/`a:b`/`Left:1` 不上浮，`x<-1`、`2026/11/19` 不误触发箭头或分数连字，`H(H)` 开 `sups`/`subs` 走 Inter 原生 `.case` 括号；
   - **GPOS 字偶距与 Inter 单次取整步进回归**：全部 Format 1 `PairSet` 按 GID 严格升序；专项检查 `ʼρ`（`U+02BC U+03C1`）全字重为 `−62`（±1）；全量 Inter 字形对字偶距与 Inter 4.1 一致（容差 `≤ 1 unit`）；全部 Inter 编码字形在命名字重下步进相对未缩放精确值误差 `≤ 1.0 unit`（杜绝二次取整）；
   - `chws` 与 `vchw` 实际挤压生效；全套标点与语言路由（含 `bopo`、破折号 1/2/3em 及竖排 3em 三段 1em 正斜体全字重无缝重叠与横向连续性、`————` 为 `3em 三段 + 1em`、西里尔/希腊默认语言 `tnum`/`zero`/`frac`/`mark`/`mkmk`、古韩文 `\u1100\u1188\u11A8` 按语言合格或拆格）；按上游保留的空 GSUB 特性记录（`ss01–ss08`、`cv01–cv13`，斜体不含 `cv11`）完整在位；
   - CL 全汉字全宽 1000（含 `巅`/`拼`/`绿`）与 `㪉㪘㪣㪰` 间距基字；
   - **表级框架逐字段对照**：静态字体与同地区、同字重、同风格上游 Sarasa Ui（Heavy 对 Bold 按规格换算），以及 VF 默认实例与 Regular 静态之间逐字段核对 `head`（`flags` 15/3、包围盒上下界 ±10、`lowestRecPPEM = 3`、`macStyle`）、`hhea`、`vhea`（`advanceHeightMax = 2000`、`yMaxExtent` ±10）、`OS/2` 全部字段（含 `ulUnicodeRange1–4`、`ulCodePageRange1–2`、`xAvgCharWidth`、`fsType`、`fsSelection`、上下标与删除线参数、全部 PANOSE）、`post`、`name` 记录键与 `STAT`；任何差异必须列在 `spec.toml` 差异清单内，否则检查失败；另检查英/本地化命名内容、`post` format 3、无 Mac name 记录与全字形 `lsb == xMin`。
2. **VF 与去重叠静态逐字形一致**：每个 unhinted 静态在命名字重下的全 `cmap` 步进与对应 VF 逐字形一致（允许临界 1 unit 取整）、墨迹外框粗检（≤ 15 unit），并以 FreeType 无 hint 光栅化在 `16 / 28 / 48 px` 逐字形比对 VF 与去重叠静态的外观（仅允许抗锯齿取整微差，杜绝去重叠丢轮廓或变形）；默认字重 400 同时执行 VF 与 Regular 静态表级框架对照。
3. **OTS 156/156 通过**：调用经 SHA-256 校验的固定 `ots-sanitize 9.3.0` 校验全部 12 VF + 72 unhinted + 72 hinted。
4. **Hinting 与光栅安全**：
   - VF 与 unhinted 静态确认不含逐字形指令、`fpgm`、`cvt`；
   - 全部 72 个 hinted 静态按 `--ft-mode`（日常 `fast` 采样 / 发版 `full` 9–128 px 全字号）逐字形执行 FreeType 严格光栅扫描（`FT_LOAD_PEDANTIC`，不允许自动 hint 回退），要求 0 报错；
   - **常设 CJK hint 位移门**：对全部 72 个 hinted 静态逐字号扫描 **12–48 px**（全 37 个字号）全部 CJK 汉字在 hint 后相对未 hint 的最大竖向点位移，常规 5 档字重与上游 Sarasa Ui 1.0.43 hinted 同码位比对（Heavy 对照同地区同风格的本版 Bold 实测分布），逐字号校验 `>2px` 数量、20–48 px 同码位退化数（非 Heavy ≤ 35）、极值位移以及 7 个哨兵字（`走、歌、男、美、哥、虎、虚`）的逐字号位移，超限即报错；
   - 每一对 hinted 与去重叠 unhinted 静态在去掉 TrueType 指令后轮廓点坐标/端点/on-curve 标志逐点一致，且 `GSUB`/`GPOS`/`GDEF`/`cmap` 逐字节一致。

## 2. 对照报告与视觉样张（人工审阅）

### 对照报告（`sarasa_pd compare`）

```powershell
# 对照上游 Sarasa Ui 1.0.43
python -E -s -X utf8 -m sarasa_pd compare --baseline upstream --cand-root fonts --out .build-cache/compare/upstream

# 对照上一发布版本（默认读 spec.toml 的 previous_version，也可显式指定）
python -E -s -X utf8 -m sarasa_pd compare --baseline project --cand-root fonts --ref-root <旧版目录> --ref-version 1.0.43.4 --out .build-cache/compare/prev
```

输出 Markdown 摘要表、**表级框架对照**节与完整 JSON 明细，覆盖全 `cmap` 差、`cmap` format 14 差、分类步进差、墨迹差（`>2` 与 `1–2`）、33 条关键排版语料差、GSUB/GPOS 语言系统路由差异及 `head`/`hhea`/`vhea`/`OS/2`/`post`/`name` 记录键逐字段差异。

### 对比样张（`sarasa_pd samples`）

```powershell
python -E -s -X utf8 -m sarasa_pd samples --cand-root fonts --ref-root <旧版目录> --ref-version 1.0.43.4 --out .build-cache/samples
```

生成两类样张供逐张审阅：

- **FreeType 6 地区并排对比图**：覆盖 9/10/11/12/14/16/32/48 px，同图并排新版 hinted、旧版 hinted 与新版 unhinted。
- **本机 Windows 96 DPI 私有加载对比图**（不修改系统已安装字体）：分别经 GDI `AddFontResourceExW(FR_PRIVATE)` ClearType 与原生 `dwrite.dll`（`IDWriteFactory::CreateFontFileReference` + `CLEARTYPE_NATURAL_SYMMETRIC`）在 12/14/16/32/48 px 实拍对比。

## 3. 确定性打包与发布步骤

### 打包与只读核验

```powershell
python -E -s -X utf8 -m sarasa_pd package --root fonts --dist dist/v1.0.43.5
```

先核对 `--root` 下的全量检查通过标记 `.check-passed.json`（确认全部 156 字体均通过 `check --stage all --ft-mode full` 且未修改），再按固定时间戳与文件权限写出全部 21 个 ZIP、`SHA256SUMS.txt` 与 `release-manifest.json`（ZIP 内 `README.md` 的相对链接会自动改写为包内可用路径或对应版本 tag 链接），随后立即执行只读核验（校验每个 ZIP 与每个内部成员的 SHA-256、成员列表精确匹配且不含旧版重复子目录文档）。

### 发布流程

1. 完成全量构建、硬门禁检查、对照报告与样张审阅，以及本地单元测试与文档同步检查。
2. 提交代码并合并至 `main`，打附注 tag `v<版本>` 并推送 `main` 与 tag；确认 GitHub Actions `check.yml` 全部通过。
3. 创建草稿 Release，上传全部 21 个 ZIP 并逐一核对 GitHub 返回的资产名称、字节数与 `sha256` 摘要与本地 `release-manifest.json` 一致。
4. 确认草稿标题、发布说明与全部 21 项资产核对无误后，直接发布为正式最新版并复核远端状态。
