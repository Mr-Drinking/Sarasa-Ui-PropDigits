# 验证与发布

本项目将“必须满足的硬性检查”（`sarasa_pd check` 与单元测试）与“人工审阅的对照与样张”（`sarasa_pd compare`、`sarasa_pd samples`）清晰分离：前者作为打包与发布门禁，后者用来快速发现与上游或前版的任何意外漂移。

## 1. 自动化验证（硬门禁）

### 单元测试（本地与 GitHub Actions CI）

```powershell
python -E -s -X utf8 -m unittest discover -s tests
```

CI 工作流 [.github/workflows/check.yml](../.github/workflows/check.yml) 在全新 Ubuntu 环境中按 [requirements.lock](../requirements.lock) 哈希锁定安装依赖，核验 `sarasa_pd env` 并运行全部单元测试（不允许跳过任何用例），包含：

- 规格文件、命名/文件名规则、环境隔离与锁文件校验；
- 归档 SHA-256 与路径穿越/符号链接拦截；
- 子集化保留 `cmap` format 14（UVS/IVS）且不泄漏未请求码位；
- VF 轴映射、`pwid` 烘焙与 UVS 保护、韩文宽度归一与 `U+FFA0` 隔离、Inter `calt` 扩充、语言系统精确合并、标点路由幂等与 `bopo`、CL A5/GDEF/OS/2 修复、`gvar` 合并与 IUP 压缩、`MVAR`/`HVAR`；
- 静态实例化元数据、A1 斜体精确重映射（含 `post` format 3 位移未编码字形）与 `cvt` 补零；
- 规则与二进制检查的反例测试（故意破坏 UVS、bit 57、轮廓、hint 等必须被拦下）；
- 确定性 21 ZIP 打包与篡改检测；
- 文档规格表格同步与全部源码/文档 UTF-8 无 BOM、LF 换行校验。

### 全量成品检查（`sarasa_pd check`）

```powershell
python -E -s -X utf8 -m sarasa_pd check --stage all --root fonts --jobs 4
```

逐字体执行以下检查（任一失败即阻止打包）：

1. **产品规则检查**（`sarasa_pd/checks/rules.py`，纯基于 GID 与几何度量，不依赖 `post` 字形名）：
   - `cmap` 覆盖与 `cmap` format 14（UVS/IVS）与同地区上游成品一致，无悬空变体目标；
   - 37 个码位默认比例宽、`pnum` 不改变默认宽度；`tnum`（含 `U+002D`）与 `tnum + zero` 严格等宽（VF 每 25 轴单位全采样）；
   - 上下文与保护回归：`1:2`/`1:`/`:2` 上浮，`1:a`/`a:2`/`Left:1` 不上浮，`x<-1`、`2026/11/19` 不误触发箭头或分数连字，`H(H)` 开 `sups`/`subs` 行为正确；
   - `chws`/`vchw` 生效；标点与语言路由（含 `bopo`、西里尔/希腊默认语言 `tnum` 与组合重音、古韩文 L+V+T）；
   - CL 全汉字全宽 1000（含 `巅`/`拼`/`绿`）与 `㪉㪘㪣㪰` 间距基字；
   - 命名、`OS/2`（含 bit 57、`usMaxContext`、`ulCodePageRange1`）、`post` format 3、无 Mac name 记录、`lsb == xMin`。
2. **VF 与静态逐字形一致**：每个 unhinted 静态在命名字重下的全 `cmap` 步进与墨迹外框与对应 VF 逐字形一致。
3. **OTS 156/156 通过**：调用固定 `ots-sanitize 9.3.0` 校验全部 12 VF + 72 unhinted + 72 hinted。
4. **Hinting 与光栅安全**：
   - VF 与 unhinted 静态确认不含逐字形指令、`fpgm`、`cvt`；
   - 全部 72 个 hinted 静态逐字形、逐字号执行 FreeType **9–128 px** 严格光栅扫描（`FT_LOAD_PEDANTIC`，不允许自动 hint 回退），要求 0 报错；
   - 每一对 hinted 与 unhinted 静态在去掉 TrueType 指令后轮廓点坐标/端点/on-curve 标志逐点一致，且 `GSUB`/`GPOS`/`GDEF`/`cmap` 逐字节一致。

## 2. 对照报告与视觉样张（人工审阅）

### 对照报告（`sarasa_pd compare`）

```powershell
# 对照上游 Sarasa Ui 1.0.43
python -E -s -X utf8 -m sarasa_pd compare --baseline upstream --cand-root fonts --out .build-cache/compare/upstream

# 对照上一发布版本
python -E -s -X utf8 -m sarasa_pd compare --baseline project --cand-root fonts --ref-root <旧版目录> --ref-version 1.0.43.3 --out .build-cache/compare/prev
```

输出 Markdown 摘要表与完整 JSON 明细，覆盖全 `cmap` 差、`cmap` format 14 差、分类步进差、墨迹差（`>2` 与 `1–2`）、33 条关键排版语料差及 GSUB/GPOS 语言系统路由差异。

### 对比样张（`sarasa_pd samples`）

```powershell
python -E -s -X utf8 -m sarasa_pd samples --cand-root fonts --ref-root <旧版目录> --ref-version 1.0.43.3 --out .build-cache/samples
```

生成两类样张供逐张审阅：

- **FreeType 6 地区并排对比图**：覆盖 9/10/11/12/14/16/32/48 px，同图并排新版 hinted、旧版 hinted 与新版 unhinted。
- **本机 Windows 96 DPI 私有加载对比图**（不修改系统已安装字体）：分别经 GDI `AddFontResourceExW(FR_PRIVATE)` ClearType 与原生 `dwrite.dll`（`IDWriteFactory::CreateFontFileReference` + `CLEARTYPE_NATURAL_SYMMETRIC`）在 12/14/16/32/48 px 实拍对比。

## 3. 确定性打包与发布步骤

### 打包与只读核验

```powershell
python -E -s -X utf8 -m sarasa_pd package --root fonts --dist dist/v1.0.43.4
```

按固定时间戳与文件权限写出全部 21 个 ZIP、`SHA256SUMS.txt` 与 `release-manifest.json`，随后立即执行只读核验（校验每个 ZIP 与每个内部成员的 SHA-256、成员列表精确匹配且不含旧版重复子目录文档）。

### 发布流程

1. 完成全量构建、硬门禁检查、对照报告与样张审阅，以及本地单元测试与文档同步检查。
2. 提交代码并合并至 `main`，打附注 tag `v<版本>` 并推送 `main` 与 tag；确认 GitHub Actions `check.yml` 全部通过。
3. 创建草稿 Release，上传全部 21 个 ZIP 并逐一核对 GitHub 返回的资产名称、字节数与 `sha256` 摘要与本地 `release-manifest.json` 一致。
4. 确认草稿标题、发布说明与全部 21 项资产核对无误后，直接发布为正式最新版并复核远端状态。
