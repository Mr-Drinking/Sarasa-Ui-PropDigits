# 与上游 Sarasa Ui 的差异

本文档区分四类内容：本项目的有意设计差异、采用 VF 单真相源跟随上游 VF 来源造成的差异、继承自上游的已知行为，以及运行环境相关的已知限制。条目编号与 [sarasa_pd/spec.toml](../sarasa_pd/spec.toml) 保持单一来源同步。

## 1. 有意差异

以下差异属于本项目的明确产品规格，每次发布均由自动化规则检查守护：

## 2. 跟随 VF 来源（与上游静态的来源差）

本项目全部 144 个静态字体均由同版本 VF 实例化生成，不再向 Sarasa 1.0.43 静态成品做 13 控点逐单位反向对齐。因此，以下差异直接源自固定上游 VF（Source Han Sans VF 2.005R、Inter VF 4.1、Shanggu Sans TC VF 1.028）与 Sarasa 1.0.43 静态成品之间的固有差异：

<!-- BEGIN SPEC:differences_source_vf -->
| 编号 | 条目 | 依据 |
| --- | --- | --- |
| `vf-single-source-metrics` | 单真相源跟随 Source Han VF 与 Inter VF 数值 | 不再向 Sarasa 静态成品做 13 控点逐单位对齐；保留 Source Han VF 的假名+句读字偶距、逐字重插值 palt/vpal 与尚古 1.028 VF 原样字形。 |
<!-- END SPEC:differences_source_vf -->

主要实测统计（对照上游 `Sarasa Ui 1.0.43` 静态 `Regular`）：

- **假名与句读字偶距**：Source Han Sans VF 自带假名与句读字偶距（如 `です。` 中 `す。` 步进由 1000 缩至 900），上游 Sarasa 静态未携带该表项；本项目直接保留 Source Han VF 原生字偶距。
- **比例排版表 `palt`/`vpal`**：Source Han Sans VF 提供随字重连续插值的 `palt`/`vpal`（例如 `ぁぉ「テスト」。`、`一ぁぉ「」。` 在各字重按 VF 曲线平滑变化），不再复制 Sarasa 静态中少数手写覆盖值。
- **Inter 缩放单次取整（≤ 1 unit）**：将 Inter 2048 upem 缩放至 1000 upem 时，`ExactCurve` 直接读取未缩放精确坐标与步进，并以非重叠分段线性支撑（`adjacent_supports`）在全部命名字重实现单次取整；相对 Inter 静态成品步进差不超过 1 unit，且 `tnum` 全部数字彼此严格等宽。
- **CL 尚古 1.028 替换差异**：上游 Sarasa Ui CL 仅叠加内置尚古 1.025 子集，本项目在 CL 使用完整 `ShangguSansTC-VF` 1.028 文件替换基底中共有汉字（码位集合仍以上游 Sarasa Ui CL 为界），因此在 `Regular` 下共有 **968 个**汉字的墨迹外框与上游相差超过 2 unit（其中 325 个相差超过 10 unit，如 `㑒`、`㑓`、`㒶`、`㓱`、`㔳`），而 SC 同条件下仅 21 个（Source Han VF 与静态来源的转换微差）。这些汉字保持尚古 1.028 VF 原生字形与位置，且全宽统一为 1000。
- **竖排破折号与省略号**：1em/2em 竖排破折号与省略号跟随 Source Han Sans VF 原生 `ccmp`/`locl`/`vert`/`vrt2`；3em 破折号在竖排通过 MultipleSubst 替换为由原生 3em 竖排字形切出的三段 1em 无缝重叠字形 `[top, middle, bottom]`（见第 1 节有意差异），无 `curs`，正斜体全字重无缝连接。

## 3. 继承自上游的已知行为

<!-- BEGIN SPEC:differences_upstream -->
| 编号 | 条目 | 依据 |
| --- | --- | --- |
| `upstream-inherited` | 继承自上游且解释得通的细节 | 包括 Ģ、加泰罗尼亚语 l·l、DFLT 无 CJK 语言系统、latn/CAT·MOL·ROM 路由、win 度量 968/241 与 hhea.ascender 969、由 〱〲 决定的 head 上下界（1323 / -549）、U+22EF 与 OS/2 码页 bit 31。 |
<!-- END SPEC:differences_upstream -->

具体包括：

- `Ģ` 与加泰罗尼亚语 `l·l` 跟随 Inter 4.1；
- `DFLT` 下不挂入 CJK 语言系统；`latn` 下的 `CAT`/`MOL`/`ROM` 保持 Inter 路由而不混入 Source Han 特性；GSUB 照上游保留无 lookup 的 `ss01–ss08`、`cv01–cv13` 空特性记录（斜体不含 `cv11`）；
- `U+22EF`（居中省略号）强制来自 Source Han 且在 `ttfautohint` 中保持未缩放保护；
- `OS/2` 码页范围 1 的 bit 31（符号字符集位）与各地区码页位跟随上游 Sarasa Ui；
- `hhea.ascent = 969`、`OS/2.sTypoAscender = 968`、`usWinAscent = 968`、`usWinDescent = 241` 沿用上游垂直度量基准。

## 4. 已知限制

- **Windows GDI `win` 度量裁切**：沿用上游 `usWinAscent = 968` / `usWinDescent = 241`，少数超高/超深字形（如部分叠加附加符号或框线字符）超出该区间，在严格按 `win` 度量裁切的 GDI 控件中边缘可能被裁。本项目不擅自拉大行高度量，实际表现以目标应用为准。
- **Android `includeFontPadding`**：`head` 全局包围盒上下界（约 `1323 / -549`）受竖排双字符 `〱〲` 决定，与上游 Sarasa Ui 一致（已通过在竖排将 3em 破折号切分为三段 1em 无缝字形，避免 Source Han 原生 3em 竖排单字形将上下界扩大至 `1808 / -1048` 与 `vhea.advanceHeightMax` 扩大至 `3000`）。Android `TextView` 默认开启 `includeFontPadding` 时首末行留白会略大于纯西文 Inter，但与上游 Sarasa Ui 相同。
- **竖排非标准连段**：3 个破折号竖排由切分后的三段 1em 无缝构成，4 个破折号按 Source Han 原生规则为 `3em（三段）+ 1em`，不额外注入 `curs`。
- **VF 与 unhinted 静态的最小 `prep`**：两者保留仅含 smart dropout 控制（`SCANCTRL`/`SCANTYPE`）的最小 `prep` 与 `gasp` 以防止极小字号下细笔画断裂，不含逐字形指令、`fpgm` 或 `cvt`；部分只检查是否存在 `prep` 表的外部脚本可能据此提示存在光栅准备程序，属于有意设计。
